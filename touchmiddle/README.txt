TouchMiddle 0.5.2 — 手勢、快捷鍵、App 規則與登入自動啟動設定

安裝位置：/Applications/TouchMiddle.app 或 ~/Applications/TouchMiddle.app
原始碼：此目錄的 Sources/ 與 Tests/

使用方式
1. 啟動 App。在「狀態與設定」確認已連接內建觸控板，並允許 TouchMiddle 的 macOS 輔助使用權限。若系統已允許但 App 仍未取得權限，重新啟動 App；本機臨時簽章重新建置後可能需要重新加入權限清單。
2. 在「手勢規則」按「新增規則」，選擇兩指雙擊、三指雙擊、三指輕點，或「兩指固定左側點擊」／「兩指固定右側點擊」。雙擊是輕點、完全放開、再輕點；不需要壓下觸控板。
3. 選擇「全域（所有 App）」或指定 App。指定 App 時，按「選擇 App…」選取其 .app。
4. 選擇「鍵盤快捷鍵」，按「錄製快捷鍵」後輸入自己的組合鍵，可包含 ⌘、⌥、⌃、⇧。錄製區只收下一組按鍵；Escape 停止錄製。也可把動作設成「中鍵（游標位置）」。
5. 勾選「啟用此規則」並儲存。確認「啟用手勢」已開啟，先碰一下觸控板，再把所有手指完全放開，完成校準。
6. 切到目標 App 執行手勢。「最近動作」顯示本次送出的 App 與動作；結果仍取決於該 App 是否支援此快捷鍵。
7. 在「狀態與設定」的「啟動設定」可開啟或關閉「登入 macOS 時自動啟動 TouchMiddle」。此設定由 macOS 登入項目管理，開機後登入目前帳號時生效；權限、設定與觸控來源正常時，啟動後手勢預設啟用。若顯示尚未獲准，按「開啟系統登入項目設定」並允許 TouchMiddle。從系統設定返回 App 時會重新讀取狀態；失敗會顯示錯誤並保留系統實際狀態。請從固定安裝位置的 .app 操作，不要從 SwiftPM 執行檔或臨時建置位置登記。

在「狀態與設定 → 選單列圖示」可開啟或關閉「在選單列顯示 TouchMiddle 圖示」。預設顯示，選擇會保留到下次啟動。隱藏圖示不會暫停手勢；若關閉設定視窗，可再次開啟 TouchMiddle.app 回到設定並恢復圖示。

首次建立規則檔時，只建立原有的「全域三指輕點 → 中鍵」。雙擊與兩指固定手勢的規則由使用者新增，不預設任何組合鍵。
每次重新啟動時，若權限、設定與觸控來源正常，手勢預設啟用，已儲存的規則會保留。啟動時尚未取得權限者，授權後需手動啟用手勢。選單列可啟用、暫停、開啟設定或結束。
編輯規則與錄製快捷鍵期間暫停手勢輸出；離開編輯後先完全放開，再開始新手勢。

規則優先順序
同一套用範圍與同一手勢只能有一條規則，可用「編輯」修改既有規則。
相同手勢有已啟用的指定 App 規則時，只執行該規則；沒有已啟用的指定規則時，使用已啟用的全域規則。指定規則停用並不禁止全域規則。
快捷鍵送到當時的前景 App PID；送出前發現 App 已切換便取消。兩次點按不能跨 App、跨 PID 或跨觸控板配成雙擊。
中鍵送到目前游標位置。在 Safari 要開啟連結的新分頁，游標需位於一般網頁連結上；空白處中鍵不會建立空白新分頁。若要建立空白新分頁，可自行錄製 ⌘T 規則。

辨識與設定
一般輕點與雙擊：預設每次輕點的接觸起始時間差不超過 65 ms，所選指數至少重疊 15 ms，持續時間不超過 250 ms，每指位移不超過觸控板的 2.5%。
兩指固定左側／右側點擊：先讓兩指保持接觸且固定至少 150 ms，再用第三指在兩指左側或右側外緣輕點。第三指放開時，固定的兩指仍須保持接觸；兩指保持接觸時可重複點擊。左右相對於固定兩指判定，不是觸控板的左右半邊，也不會自行指定滑鼠左鍵或右鍵。
兩指固定手勢使用相同的每指位移限制；單次輕點最長時間只計第三指的接觸，固定兩指的等待時間另計。固定兩指移動超過限制、放開其中一指或切換 App 會取消目前手勢；完全放開後再開始新手勢。
雙擊間隔預設 350 ms，從第一下完全放開計到第二下開始接觸；第二下也必須在單次點按時間限制內完全放開。兩下的指數需相同，位置也需接近。
只有當目前 App 同時適用三指輕點與三指雙擊規則時，第一下三指輕點會等待雙擊間隔；第二下成功時只觸發雙擊。未設定三指雙擊時，三指輕點仍在放開後立即觸發。
單次完成動作後有 250 ms 冷卻；雙擊後另抑制同一快速點按串中的第三下，避免多送三指輕點。
「狀態與設定」可調整可移動距離、單次最長時間與雙擊間隔，按「套用點按設定」後生效。
移動、捲動、四指、取消接觸與無效影格會取消候選；超過 120 ms 的軟體排隊延遲也會取消目前手勢。啟用、設定更新與喚醒後會重新校準。
本版接收觸控資料並送出動作，沒有攔截 macOS 原有手勢；原生手勢可能同時觸發。

規則與診斷檔案
規則存放於 ~/Library/Application Support/TouchMiddle/rules.json；儲存時以權限 0600 的暫存檔原子更換。無效內容與連結檔會報錯，不會悄悄覆寫成預設規則。
一般診斷存放於 ~/Library/Application Support/TouchMiddle/Diagnostics/，檔案權限 0600，只記錄狀態與辨識／輸出結果。
「辨識」計算符合條件的手勢，包括暫停時的唯讀辨識；「送出」表示已呼叫事件輸出；「觀察到事件」表示 App 的事件監視器看到同一標記的按下與放開。這些數字不等於目標 App 已完成快捷鍵動作，仍需實際結果驗收。
本機驗收時，直接送到 PID 的鍵盤事件已被獨立接收端收到，但 App 自己的事件監視器仍為 0；此數字為 0 不能單獨判定快捷鍵送出失敗。
--trace --log /新的絕對路徑.jsonl 會另記觸控座標、影格、前景 App 與處理延遲，用於本機驗收。App 拒絕覆寫既有診斷檔或使用連結檔。
「4 秒後測試中鍵」只測手動中鍵輸出，請先把游標移到安全位置；它不能替代手勢或快捷鍵驗收。
不會上傳規則或診斷。本版包含 GitHub 更新檢查：App 執行期間每 24 小時檢查正式版與測試版，也可用選單列「檢查更新…」或「狀態與設定 → 軟體更新」手動檢查。新版內容會在更新視窗顯示，按「開啟下載頁」到 GitHub 下載後手動替換 App。重啟保留檢查時間；同一新版只自動提示一次，手動檢查可再次顯示。查詢失敗會顯示錯誤，限流期間須等待指定時間。登入項目只有在操作者開啟設定時才會登記；建置與啟動 App 本身不會自動登記。

建置與驗證
Tools/build-app.sh --output /全新絕對路徑/TouchMiddle.app
xcrun swift test --scratch-path /tmp/touchmiddle-tests
需本機 Xcode/Swift；不需要外部 Swift 套件。建置腳本拒絕覆寫既存 App。
本機有 ~/Library/Application Support/TouchMiddle/Signing/identity.json 時，建置使用其中的固定 Code Signing 憑證指紋；私鑰留在鑰匙圈。設定無效或憑證不存在時中止，不會改用 ad-hoc。沒有本機設定時維持原有 ad-hoc；也可用 --signing-identity SHA1 指定憑證，或 --ad-hoc 明確選擇臨時簽章。測試版打包固定採 ad-hoc。
首次從 ad-hoc 更換簽章後需重新授權；不同建置須符合相同的簽章身分要求，才可能沿用權限。固定憑證不會自動授予輔助使用權限，也不等於 Apple Developer ID 或公證。
Tools/touch-probe.c 是唯讀觸控探測；Tools/MiddleEventReceiver.swift 與 Tools/KeyboardEventReceiver.swift 是獨立接收端。Tools/KeyboardEventFieldsCheck.swift 可驗證快捷鍵事件欄位，不會送出事件。

驗收狀態與限制
0.4.0-beta.1 首次於公開包提供兩指固定左側／右側點擊及其他擴充手勢（合計 17 種），並支援組合鍵觸發條件。新增手勢的真人觸控板操作及目標 App 動作尚未完成驗收；以下歷史結果不涵蓋新增手勢。
0.2.0 自動測試：68 項核心／轉換／手勢／規則測試通過；另有 19 組快捷鍵事件欄位檢查通過，欄位檢查未送出事件。
0.2.0 實機驗收：錄製 ⌘Q、⌘W 時，快捷鍵保留在錄製區，App 未結束或關閉視窗；錄製的快捷鍵可儲存，重啟後仍保留。兩個獨立接收端共收到首輪 24 組按下／放開，與輸出標記、目標 PID、鍵碼及修飾鍵逐一相符；已啟用的 App 專屬規則優先於全域規則。
分段重測：停用 App 專屬規則後，在同一 App 做兩指／三指雙擊各 5 次，接收端各收到 5 組全域快捷鍵。另一次只做單指移動、雙指捲動與三指滑動各 5 次，沒有新增辨識或快捷鍵，接收端維持 14/14。
首輪 App 專屬視窗的三指雙擊只收到 4/5；另多出的 4 次兩指雙擊，使用者無法確認是否為補做點按或誤觸。後續分段測試通過，但首輪漏判原因仍 unclear；本輪結果不保證任意手勢或長時間使用皆無誤觸。接收端確認事件送達，不代表每個第三方 App 都會執行該快捷鍵。
本輪測試規則已移除，原有三指輕點中鍵規則已恢復。正常重啟後觸控板連線與輔助使用權限已確認；手勢預設暫停，請新增自己的雙擊規則後再啟用。
0.1.0 歷史證據：原有 32 項核心／轉換測試通過；獨立接收端曾收到 10 組中鍵按下／放開，與三指辨識標記逐一相符，後續滑動／捲動沒有新增中鍵；Safari 普通 HTML 連結曾收到 DOM button 1 事件，分頁由 3 增至 4。這些證據只確認舊版三指輕點／中鍵，不代表新版雙擊或快捷鍵已驗收。
0.2.0 驗收摘要位於工作區 outputs/touchmiddle-0.2.0-verification.json；原始驗收記錄位於 work/touchmiddle-rules-validation/。歷史中鍵紀錄位於 outputs/touchmiddle-verification.json 與 work/safari-middle-debug/result.json。
本機環境為 Apple M5、內建觸控板、macOS 27.0.1。套件宣告最低 macOS 14，不代表已測試所有 macOS 14–27 裝置。
使用 MultitouchSupport 私有 framework，目前為公開分享前的測試版；macOS 升級後需重新驗證。未支援外接 Magic Trackpad、中鍵拖曳或其他 BTT 功能。
新增登入自動啟動設定的實際登記／取消與重新登入驗收尚未執行；上述 0.2.0 歷史驗收不涵蓋此功能。
真實 sleep/wake、長時間壓力與所有掌心接觸尚未驗證。原生框架沒有經本機驗證的掌心分類，App 不承諾辨別任意掌心形狀。

未發布：擴充手勢與組合鍵

新增一指固定左／右輕點、兩指固定第三指上／下滑、四指輕點、三指長按、
四角兩指輕點、兩指固定左／右雙擊，共 12 種，含原有手勢共 17 種。

在規則編輯器的「需按住的按鍵」選擇 ⌘／⌥／⌃／⇧，可同時選多個。
未勾選代表必須不按這四種按鍵；採精確比對，不會退回沒有組合鍵的規則。
先按住指定鍵再操作手勢，直到觸發完成。途中換鍵、切換 App 或 PID 會取消。
組合鍵是觸發條件；實際輸出的快捷鍵仍由「觸發動作」設定。

四角：兩指都必須在同一角落的寬、高各 25% 區域，角落輕點優先於一般兩指雙擊。
三指長按：三指共同固定至少 500 ms，第一指接觸後 2 秒內完全放開時觸發。
第三指上／下滑：兩指固定至少 150 ms，第三指垂直位移至少高度 6%，在單次輕點時間內放開。
固定手指雙擊：每次只放開操作手指；第二次須在雙擊間隔內開始。
同側單擊與雙擊一起啟用時，單擊延後到雙擊間隔結束；期間固定手指也需保持接觸。
一指與兩指固定規則並用時，先固定一指 150 ms 後加入第二指會進入一指固定操作；
要使用兩指固定，請讓兩個固定手指一起落下。

新儲存的規則格式為 version 2，仍可讀取 version 1 舊規則。舊版 App 無法讀取新格式。
新增手勢與實體組合鍵的真人驗收尚未完成；macOS 原生動作仍可能同時觸發。

## 實機結果

| 驗證項目 | 已觀察結果 |
| --- | --- |
| 快捷鍵錄製 | 錄製 ⌘Q、⌘W 時未結束 App 或關閉視窗；規則儲存及重啟回讀一致。 |
| 全域與 App 規則 | 首輪 24 次輸出均由獨立接收端收到一組按下／放開；標記、PID、鍵碼及修飾鍵相符。App 專屬規則優先。 |
| 停用 App 規則後回退全域 | 在同一 App 進行兩指／三指雙擊各 5 次，兩種全域快捷鍵各收到 5 組。 |
| 分段滑動測試 | 單指移動、雙指捲動與三指滑動各 5 次，沒有新增辨識、輸出或接收端事件。 |
| 設定錯誤修復 | 無效雙擊間隔顯示錯誤並停止來源；套用有效設定後來源恢復，整輪暫停輸出。 |
| 正常啟動 | 內建觸控板連線、輔助使用與事件權限有效。預設暫停；測試規則已移除。 |

## 限制與未確認項目

- 首輪 App 專屬視窗的三指雙擊收到 4/5；另多出的 4 次兩指雙擊，使用者無法確認是否為補做點按或誤觸，原因仍為 `unclear`。後續分段重測通過，不能據此保證任意手勢或長時間使用皆無漏判或誤觸。
- 獨立接收端確認鍵盤事件送達；未驗證每個第三方 App 是否執行對應動作。
- 直接送到 PID 的鍵盤事件在獨立接收端已收到，但 App 自己的事件監視器為 0；此數字不能單獨判定輸出失敗。
- 真實 sleep/wake、長時間壓力、任意掌心接觸、外接觸控板及其他 macOS 版本尚未驗證。
- 本版沒有攔截 macOS 原有手勢；原生手勢可能同時觸發。
- 實機驗收使用 Apple M5、內建觸控板與 macOS 27.0.1。使用 MultitouchSupport 私有 framework；系統升級後需重新驗證。

完整證據位於本機 `outputs/touchmiddle-0.2.0-verification.json` 與 `work/touchmiddle-rules-validation/`。
